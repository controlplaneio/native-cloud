Metadata keys in `native.cloud` are designed to be applied across several distinct operational contexts in cloud native infrastructure. Each context serves different operational roles, has specific syntax and size constraints, and integrates with different control plane components.

## Context Overview

The ontology supports five primary metadata contexts across Kubernetes and container ecosystems:

## Comparison Matrix

| Context | Target Scope | Value Limit | Syntax Constraints | Primary Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **Annotation** | All Kubernetes Objects | Unlimited (etcd object limits) | UTF-8 string, structured JSON/YAML | Tooling config, audit metadata, non-identifying info |
| **Label** | All Kubernetes Objects | 63 characters max | Alphanumeric, `-`, `_`, `.`, DNS format | Selectors, grouping, scheduling, routing |
| **Taint** | Kubernetes Nodes | 63 characters (value) | Key/value with effect (`NoSchedule`, etc.) | Node isolation, dedicated workloads |
| **Resource Claim** | Dynamic Resource Allocation | Driver-dependent | Structured claim parameters | GPU/FPGA allocation, specialized hardware |
| **OCI Annotation** | OCI Images & Artifacts | Registry-dependent | Reverse domain notation keys | Build provenance, source repo, image descriptions |

## Choosing the Right Context

When choosing where to apply an ontology key, consider how downstream tooling interacts with the metadata:

1. **Use Labels** when controllers, ingress routers, Prometheus scrapers, or operators need to filter, select, or query resources (`kubectl get pods -l ...`).
2. **Use Annotations** when recording timestamps, Git commit hashes, issue tracker URLs, policy references, or complex structured data that controllers read directly without querying by selector.
3. **Use Taints** when nodes must repel workloads by default, reserving compute for specific pods that declare matching tolerations.
4. **Use Resource Claims** when workloads require declarative, lifecycle-managed access to heterogeneous physical devices.
5. **Use OCI Annotations** when metadata needs to travel alongside container images through registries, build pipelines, and artifact scanners.

:::tip[Syntax Verification]
Always ensure your key values conform to the syntax requirements for your chosen context. Labels in particular strictly enforce alphanumeric characters and length limits.
:::
